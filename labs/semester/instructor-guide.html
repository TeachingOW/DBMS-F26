Design checkpoints

S+={S,StudentName}; CT+={C,T,CourseTitle,Instructor,Office}; SCT+ contains all attributes. S,C,T never occur on any FD right-hand side, so every key must contain all three. The proposed five-way decomposition is BCNF for the supplied FDs and preserves them. Each extraction joins through a determinant that is a key of the extracted relation, supporting losslessness.

For AB→C, C→B, candidate keys are AB and AC. All attributes are prime, so R is 3NF; C is not a superkey, so it violates BCNF. CB/AC is lossless because C→CB, but AB→C is not preserved locally. Example spurious-tuple case with no FDs: R={(a1,b,c1),(a2,b,c2)}; AB join BC adds (a1,b,c2),(a2,b,c1).

Performance checkpoints

80 records/page; 1,250 pages; ceil(1250/11)=114 initial runs; merges 114→12→2→1, so three merge passes plus run generation. Total 2×1250×4=10,000 page I/Os under the stated model. Cold point lookup: three index pages plus one heap page = four; cached root reduces new reads by one.

Page nested-loop: R outer 201,000; S outer 200,200. Block nested-loop: R outer 1,000+50×200=11,000; S outer 200+10×1,000=10,200. Two-pass hash join=3,600, conditional on partitions fitting. Do not grade exact milliseconds or require an index scan on a broad predicate.

Transactions and operations checkpoints

Successful transfer yields 75/125 and total 200. Simplified crash trace recovers A=80,B=120: T1 committed, T2 incomplete. S1 has T1→T2 and is conflict-serializable, but T2 reads T1 before T1 commits; it is recoverable under the listed commit order, not cascadeless. S2 has edges both ways and is not conflict-serializable. Deadlock victim is nondeterministic; both sessions must clean up. READ COMMITTED can see B’s intervening commit on the second read; REPEATABLE READ’s established snapshot does not. A guarded last-item update allows only one decrement.

Midnight backup / 15:00 failure can lose up to 15 hours of later changes; 40-minute restore exceeds the stated 10-minute objective. A restored table count does not prove identical values. Least-privilege checks must show SELECT events allowed, UPDATE events and SELECT accounts denied.

Application and project checkpoints

Capacity-one event: exactly one of two different-student requests succeeds. Duplicate request produces no extra row. Exceptions before commit leave no booking. Parameter binding preserves quoted text as data. This application-level locking convention requires all writers to participate.

Midterm debugging fixes: keep paid filter in ON (or conditional aggregate), group by event ID plus title, count the child key, and preserve zero-booking groups. Final demos should show setup, a business query, successful transaction, failure/rollback, one measured optimization, and restore evidence.
