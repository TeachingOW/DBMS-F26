Foundations and reproducible SQL

Use PostgreSQL 16+ and a dedicated empty teaching database. These exercises support meetings 1, 2, and 5. Start with setup.sql; it creates only the course32 schema and deliberately fails if that schema already exists. For a repeat run, create a fresh teaching database instead of dropping existing work.

Meeting 1: requirements before syntax

A campus currently keeps event registrations in separate spreadsheets. Two staff members can edit seats remaining; a student may register twice; event titles are copied into every row. In pairs, identify three inconsistent states and assign each to a key, foreign key, transaction, or application rule. Explain what a DBMS can enforce and what still requires a precise requirement.

Meeting 2: setup and integrity lab

Budget: 10 minutes predictions, 15 setup demonstration, 15 guided constraints, 50 independent work, 10 debrief.

  1. Run setup.sql. Verify 5 students, 4 events, 6 bookings, and total account balance 200.00.
  2. Display student names alphabetically; display events with fee at least 20; return event titles and capacity only.
  3. In separate BEGIN/ROLLBACK blocks, try a duplicate student ID, a booking for student 999, fee -1, and a NULL student name. Record the constraint responsible. After an error issue ROLLBACK before the next test.
  4. Choose types for money, event dates, email, and capacity. Explain why numeric money and integer capacity express different domains.
  5. Add one valid student and booking in a transaction, inspect them, then roll back. Verify original counts.

Meeting 5: query exercises

  1. Find students without email. Explain why email = NULL does not answer the question.
  2. Find names beginning with A, events costing between 10 and 20 inclusive, and bookings in January 2026.
  3. Predict email IS NULL, email = 'x', and NOT(email = 'x') for a NULL email.
  4. Show the two most expensive events with deterministic ordering for ties.
  5. Raise event 101’s fee by 5 within a transaction; compare before, during, and after ROLLBACK.
  6. Insert a student whose name contains an apostrophe. Explain SQL escaping now and parameter binding later.
  7. Write a DELETE that targets exactly one booking; test inside a rolled-back transaction.
  8. Explain why rows have no guaranteed display order without ORDER BY.

Submit: SQL, predicted and actual outputs, a four-row constraint log, and corrections. Stretch: design tests that distinguish empty string from NULL and missing row from a row containing NULL.
