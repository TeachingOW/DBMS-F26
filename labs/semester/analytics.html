Meetings 13–14. Load setup.sql. The dataset deliberately includes tied revenues and a branching hierarchy.

Meeting 13: analytics (100 minutes)

10 review, 25 windows and frames, 20 worked ranking example, 35 independent tasks, 10 debrief.

  1. Aggregate paid event revenue first: SQL 40, Design 30, Data 30, Graph 0. Rank using RANK and DENSE_RANK over revenue descending. Explain the tie and the gap.
  2. Use ROW_NUMBER with revenue descending and event ID as a tie-breaker. Why should the ranking function itself omit the event ID if revenue ties must share rank?
  3. Calculate a cumulative booking count ordered by booked_at, student_id, event_id with ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW.
  4. Calculate each event’s share of total paid revenue without collapsing the output rows.
  5. Use LAG on daily booking counts to compute the change since the preceding observed day. Explain why that is not necessarily the previous calendar day.

Meeting 14: recursive hierarchy (100 minutes)

10 review, 15 recursion model, 15 worked anchor/step, 50 lab, 10 debrief.

  1. Traverse topics starting at Database. Return id, name, depth, and an array path.
  2. Predict Database at depth 0; SQL and Systems at 1; Joins and Transactions at 2.
  3. Add an explicit depth bound and a visited-ID test. Explain what each protects against.
  4. In a rolled-back transaction make Database a child of Joins. Explain why a root-based anchor now misses that component; start at id=1 and use a path guard to terminate.
  5. Compare the recursive query with a fixed two-level self-join. Which changes if a new level is added?

Submit: SQL, outputs, ranking/frame explanation, and a termination argument. Stretch: return each node’s descendant count and build a calendar series before using LAG.
