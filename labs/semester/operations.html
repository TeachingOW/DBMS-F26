Restore verification and least-privilege exercise

Meeting 26, 100 minutes: 10 recovery recap, 15 instructor demo, 15 guided fingerprint, 50 restore/permissions exercise, 10 debrief. Prerequisites: PostgreSQL client programs on PATH, a disposable teaching database named dbms_course32 containing the fixture, and an instructor-provided role permitted to create a separate restore database. Use an instructor demonstration if students do not have role-management rights; do not grant superuser access for this exercise.

Part A: restore, do not merely create a dump

  1. Record counts for students, events, bookings, and accounts; record SUM(balance) and paid revenue by event. Save the outputs.
  2. From a terminal run the commands below. Replace lab_owner with your teaching account; authentication uses the normal PostgreSQL client configuration/prompt. Use a new restore database name if it already exists.
  3. Connect to dbms_course32_restore. Repeat the fingerprints and verify the same constraints by attempting an invalid booking in a rolled-back transaction.
  4. After the dump, change a fee only in the source database. Verify the restored snapshot does not include the later change. Explain why a logical backup alone cannot recover that later update.
pg_dump -U lab_owner -d dbms_course32 -Fc -f course32.dump
createdb -U lab_owner dbms_course32_restore
pg_restore -U lab_owner -d dbms_course32_restore --no-owner --no-privileges --exit-on-error course32.dump

Part B: least privilege

An instructor/admin creates a NOLOGIN role once and permits the teaching owner to SET ROLE to it. The schema owner grants only USAGE on course32 and SELECT on events. Run each attempted forbidden statement in its own transaction or autocommit mode so one error does not hide the next test.

-- Instructor/admin, once in a dedicated teaching environment:
CREATE ROLE course32_reader NOLOGIN;
GRANT course32_reader TO lab_owner;
-- Schema owner:
GRANT USAGE ON SCHEMA course32 TO course32_reader;
GRANT SELECT ON course32.events TO course32_reader;
SET ROLE course32_reader;
SELECT id,title FROM course32.events; -- allowed
UPDATE course32.events SET fee=0 WHERE id=101; -- denied
SELECT * FROM course32.accounts; -- denied
RESET ROLE;

Record a matrix of role × operation × expected/observed outcome. Explain why a real application login should be narrowly privileged rather than using the database owner.

Recovery objectives

A backup is taken at midnight, the service fails at 15:00, and restore takes 40 minutes. With no later recoverable log, what is the possible data-loss interval? If the business requires at most five minutes of data loss and ten minutes of downtime, explain why this backup plan is inadequate. Distinguish RPO, RTO, replication, logical backup, and WAL-based crash recovery.

Submit: command transcript with no credentials, matching fingerprints, constraint check, permission matrix, and recovery recommendation. Stretch: explain what a table-level count alone can fail to detect; compare values and keys as well.
